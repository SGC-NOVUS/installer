# NOVUS Installer — Безопасность

**Версия:** 1.0.0

---

## 1. Модель угроз

Инсталлятор выполняется с root-правами на чистом VPS и управляет установкой всех компонентов. Угрозы:

- **Неавторизованный доступ:** злоумышленник подключается к веб-интерфейсу установщика
- **Перехват токена:** токен в URL может быть перехвачен
- **Shell injection:** вредоносный ввод в полях формы (домен, email, пароли)
- **Утечка учётных данных:** пароли БД и админа в аргументах процессов
- **Остаточные файлы:** временные файлы с чувствительными данными

---

## 2. Защита веб-интерфейса

### Токен-аутентификация

1. При запуске генерируется случайный 32-байтный токен (`crypto/rand`)
2. Токен передаётся в URL: `http://<ip>:8080/?token=<random>`
3. После первого успешного запроса — HttpOnly cookie
4. Постоянное сравнение: constant-time (`crypto/subtle.ConstantTimeCompare`)
5. Попытки подбора не ограничены (веб-сервер слушает только localhost в production)

### HTTPS

- В production режиме веб-сервер автоматически редиректит на HTTPS
- Используется self-signed сертификат (только для процесса установки)

---

## 3. Защита от инъекций

### Shell Injection Prevention

- **Домен:** валидация через `net.ParseIP` или regex `^[a-zA-Z0-9]([a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?$`
- **Email:** валидация через `net/mail.ParseAddress`
- **Пароли/секреты:** передача через tmpfile (JSON), не через аргументы командной строки
- **URL:** парсинг через `url.Parse` с allowlist-хостов
- **Shell quoting:** все переменные в shell-командах экранируются через `shellQuote()`

### SQL Injection Prevention

- Пароли БД экранируются через `escapeSQLLiteral()`
- SQL-запросы передаются через `printf` во временный файл (не через here-doc)

### Path Traversal Prevention

- Все пути нормализуются через `filepath.Clean`
- Проверка на абсолютные пути
- Создание директорий с явными правами (0700/0750)

---

## 4. Защита учётных данных

### Admin Creation (tmpfile strategy)

Учётные данные администратора **никогда** не передаются через аргументы командной строки:

1. PHP-скрипт записывается во временный файл через `cat << 'NOVUSEOF'`
2. Учётные данные (email + пароль) записываются в отдельный JSON-файл через `printf`
3. PHP-скрипт читает учётные данные из JSON-файла
4. Оба временных файла удаляются (`rm -f`, `@unlink`)

Это предотвращает:
- Утечку пароля через `/proc/<pid>/cmdline`
- Утечку пароля через `ps aux`
- Утечку пароля через history

### Пароли БД

- Передаются через `printf` в SQL-файл
- SQL-файл удаляется сразу после выполнения
- Пароли ротируются при повторной установке

## 5. Права доступа

| Путь | Права | Владелец |
|------|-------|----------|
| `/etc/novus/` | 0750 | root:root |
| `/etc/novus/secrets/` | 0700 | root:root |
| `/etc/novus/secrets/master.key` | 0600 | root:root |
| `/etc/novus/secrets/*.env` | 0600 | root:root |
| `/var/www/novus/` | 0750 | www-data:www-data |
| `/var/www/novus/storage/` | 0775 | www-data:www-data |
| `/var/log/novus-installer/` | 0700 | root:root |

---

## 6. Аудит

Все шаги установки логируются в JSON-формате:

```json
{
  "ts": "2026-06-20T10:30:00Z",
  "step": "mariadb_configuration",
  "ok": true,
  "duration_ms": 1234
}
```

Лог-файл: `/var/log/novus-installer/audit.log`

---

## 7. Самоуничтожение

После успешной установки:
1. Бинарник инсталлятора удаляет сам себя (`os.Remove(os.Args[0])`)
2. Временные файлы в `/tmp/novus-*` удаляются
3. Nginx site config инсталлятора удаляется
4. В production режиме — без возможности восстановления

В `--dev` режиме самоуничтожение отключено.

---

## 8. Остаточные риски

| Риск | Смягчение |
|------|-----------|
| Токен в URL при первом запросе | Одноразовый, немедленно заменяется на HttpOnly cookie |
| Self-signed TLS | Приемлемо для одноразового процесса установки |
| GitHub PAT в env | Не логируется, не сохраняется на диск |
| Доступ к веб-интерфейсу по IP | В production — только localhost после установки |
